Carousel

A carousel shows a row of slides inside one card. People move through it with arrow buttons, dots, the keyboard, or by swiping. It never moves on its own.

Image Carousel

Used for: showing a set of screens or images with a short title and text for each. The Figma version is 936px wide, with 340px slides.

Switch the device to see the layout change. It follows the width of its frame (936px, 810px or 416px), not the window.

Anatomy

  1. Panel: white card that holds everything.
  2. Page title: small eyebrow label in Text/Secondary.
  3. Description: Medium 20px heading in Text/Title.
  4. Viewport: the row of slides. It scrolls sideways and snaps to each slide.
  5. Slide: a Surface/Card Alt card with a title, text and an image.
  6. Controls: previous button, one dot per slide, next button.

Responsive Layouts

The carousel keeps the same padding, slide size and image height on every device. Only the width changes, so the number of slides in view changes with it.

States

  • Arrow button: default Control/Background (#272744), hover Button/Hover (#8B6D9C), disabled Button/Disabled (#565656) at the first and last slide.
  • Dot: active is Control/Background, inactive is Control/Inactive (#6B6E8C).
  • Focus: 3px solid #272744 outline with 3px offset on the buttons, the dots and the viewport (provisional, not in Figma).

JavaScript behavior

  • Previous and next scroll the viewport by one slide. The dots scroll to their slide.
  • The arrow keys scroll one slide when the viewport has focus.
  • The active dot, the disabled state of the arrows, and a hidden "Slide 2 of 5" status message update as the track scrolls. See js/carousel.js.
  • There is no autoplay.

Accessibility

  • Roles: the panel is a <section> with aria-roledescription="carousel" and a name from its heading (aria-labelledby). Each slide is role="group" with aria-roledescription="slide" and a label such as "2 of 5".
  • Buttons: the arrows and dots are real <button> elements. The arrow glyphs are aria-hidden, and the buttons are named "Previous slide" and "Next slide". Each dot is named "Go to slide 3" and the active one has aria-current="true".
  • Disabled arrows: use aria-disabled="true" instead of the disabled attribute, so keyboard focus is not lost when the user reaches the end.
  • Keyboard: Tab reaches the viewport, the arrows and the dots in reading order. Enter or Space activates a button. Left and Right arrow keys move between slides when the viewport has focus. The viewport has tabindex="0" so keyboard users can scroll it, and a visible focus outline.
  • No autoplay: moving content that starts by itself must have a pause button (WCAG 2.2.2). This design has none, so never add autoplay without one.
  • Announcements: a polite live region says "Slide 2 of 5" when the slide changes. Don't put aria-live on the track itself, because it would read every slide.
  • Contrast: arrow glyph (Text/On Nav) on Control/Background is 13.29:1. Slide text is 19.41:1 on Surface/Card Alt. Dots are UI shapes and need 3:1: the inactive dot is 4.96:1 on white and the active dot is 14.38:1.
  • Not by color alone: the active dot differs from the others only by color, and the two dots are about 2.9:1 apart. The "Slide 2 of 5" message and aria-current cover screen readers. For sighted users, consider making the active dot wider (a design decision).
  • Target size: the arrows are 40px in Figma, and an invisible 2px extension gives 44 by 44px. The dots are 8px, so each one has a 20 by 32px hit area. That meets WCAG 2.2 (24px minimum) when the spacing is included.
  • Images: real slide images need alt text that says what the screen shows. A pure placeholder uses role="img" and an aria-label.
  • Touch and motion: swiping works because the track scrolls natively. Smooth scrolling and the button transition turn off when the user prefers reduced motion.
  • Hidden slides: every slide stays in the page, so screen reader users can read all of them in order and don't need the controls to reach content.

Do's and Don'ts

✓ Do

  • Use one dot for each slide.
  • Let the user control the movement. Snap to a slide.
  • Keep slide titles short and write alt text for every image.
  • Keep slides the same width and the same image height.
  • Show part of the next slide so people see that there is more.

✕ Don't

  • Don't autoplay or loop forever.
  • Don't hide important content only in later slides.
  • Don't remove the focus outline on the buttons or the track.
  • Don't use the arrows without accessible names.
  • Don't put a carousel inside another carousel.
